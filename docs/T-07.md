# T-07: Extract Static Assets (JS & CSS)

> **Status:** Implemented  
> **Task Reference:** `T-07` ([USER_STORY_MAP.md](USER_STORY_MAP.md))

## Goal

Separate presentation CSS and client-side JavaScript out of Thymeleaf HTML templates into dedicated static files under `src/main/resources/static/css/` and `src/main/resources/static/js/` so browser caching, asset maintainability, and CSRF-aware `fetch()` calls work cleanly.

## Implementation

### 1. Extracted Stylesheets (`src/main/resources/static/css/`)
- `common.css`: shared `:root` design tokens and box-sizing reset.
- `auth.css`: login & registration card styles.
- `registration-success.css`, `dashboard.css`, `planner.css`, `profile.css`, `faq.css`, `advisor.css`, `copilot.css`: page and widget styles extracted cleanly with zero `<style>` tags left in `.html` templates.

### 2. Extracted Scripts (`src/main/resources/static/js/`)
- `common.js`: provides `window.advisorCsrfHeaders()` reading `<meta name="_csrf">` and `<meta name="_csrf_header">`.
- `login.js`, `register.js`, `profile.js`, `faq.js`: extracted client validation and UI event handlers loaded via `<script defer>`.
- `planner.js`: reads initial cart & completed course state from `#planner-state` DOM `data-*` attributes instead of `th:inline="javascript"`, and attaches CSRF headers to cart/enrollment `fetch()` calls.
- `copilot.js`: floating copilot drawer logic with CSRF headers attached on `/dashboard/chat` and `/planner/cart/add` `fetch()` calls.

## Verification

- [StaticAssetsArchitectureTest.java](../src/test/java/kz/edu/sdu/advisor/ui/StaticAssetsArchitectureTest.java) verifies all templates contain zero `<style>` tags and zero inline `<script>` bodies, and all static CSS/JS endpoints return `200 OK` without auth redirects.
